## Windows: the C++ build tools are required

The MSVC Rust toolchain links with Microsoft's `link.exe` and the Windows SDK
libraries (`kernel32.lib` etc.). Without the SDK, `cargo check` works for
plain code, but `cargo build`, `cargo test` and any dependency with a build
script or proc macro fail. Install the "Desktop development with C++"
workload:

```sh
"C:\Program Files (x86)\Microsoft Visual Studio\Installer\setup.exe" modify --installPath "C:\Program Files\Microsoft Visual Studio\18\Community" --add Microsoft.VisualStudio.Workload.NativeDesktop --includeRecommended
```

**Git Bash gotcha:** Git ships its own `/usr/bin/link.exe` (a Unix tool) that
shadows Microsoft's. Run `cargo` from PowerShell or cmd, or a Git Bash where
`/usr/bin` comes after the MSVC paths. Also, `cargo` may not be on Git Bash's
`PATH`; it lives in `~/.cargo/bin`.

## Install Rust

1. Download and run `rustup-init.exe` from <https://rustup.rs>.
   On Windows it will ask for the MSVC build tools; accept.
2. Open a new terminal and check:
   ```sh
   cargo --version
   rustc --version
   ```
3. Add the WebAssembly target (needed from M1, but check it early in M0):
   ```sh
   rustup target add wasm32-unknown-unknown
   ```

## Web app (M1)

1. Node.js 22+ (Vitest 5 requires it; this machine: 24).
2. The WASM binding generator, at exactly the library's version (D-007):
   ```sh
   cargo install wasm-bindgen-cli --version 0.2.130 --locked
   ```
3. Then:
   ```sh
   cd web
   npm install
   npm run dev        # builds the WASM (npm run wasm) then serves :3000
   ```

Notes:

- `src/wasm/` is generated by `npm run wasm`; on a fresh clone run it once
  before `npm run typecheck` (the worker imports the generated glue).
- On Windows run npm from PowerShell or cmd (same `link.exe` issue as above).
- End-to-end tests are opt-in: `npx playwright install chromium` once, then
  `npm run e2e`. `PW_GPU=1` makes Playwright use the real GPU (Windows,
  Direct3D); otherwise WebGL runs in software and is slow.
- `E2E_BASE_URL=http://localhost:3000` runs the end-to-end tests against a
  running dev server instead of a static build.
- `npm run measure` (browser; `MEASURE_SOLVER=kestrel` for Kestrel's own
  solver) and `cargo run --release -p kestrel-wasm --example
  bench_solvers` (native, both solvers) time the planner.
- The commentary clips in `web/public/voice/` are generated. To change a
  line: edit `web/src/lib/ship/phrases.ts`, then run
  `web/scripts/make-voice.mjs` as its header describes (it needs two npm
  packages installed in a scratch folder, not in the project, and downloads
  an open text-to-speech model of about 90 MB on first use).

## Test policy

- `cargo test` must stay under two minutes for the whole suite.
- Slow tests (long simulations, benchmarks) go behind an opt-in flag
  (e.g. `#[ignore]` plus `cargo test -- --ignored`) and never run by default.
